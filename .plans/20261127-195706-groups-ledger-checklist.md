# Plan: Project groups, the group ledger and the checklist

- **Base**: main
- **Parent**: `.plans/20261123-100855-orchestrator-parent.md`

## Goal

The owner sees one checklist per group of repos (for example `acme-api` + `acme-web` + `acme-e2e`) instead of five chats and five lists. The checklist shows three things:

- The goals, holds and notes. People and agents write them in one Markdown file per group, `ledger.md`. A compaction loses nothing, because the state is in the file, not in the chat.
- The chain ticket → plan → step → PR. The server computes it from each plan's `- **Tickets**:` line, its `- **Waits for**:` lines, its run report and its PR. It is never stored, so it is never stale.
- An empty "Questions" area. Phase 4 connects it to the question source (GitHub issues first).

This is plan 2a of phase 2 ("Project groups and the ledger") of the orchestrator parent plan. Phase 3 (the conductor) reads `GET /api/ledger` and `ledger.md`. The owner can try it alone: put `"group": "acme-product"` on two projects, open ☑ Checklist, and see each ticket with its plans and PRs.

Example, end to end:
1. The registry has `acme-api` and `acme-web`, both with `"group": "acme-product"`.
2. `acme-api` has a plan `20261127-100000-invoice-export.md` with `- **Tickets**: #41` and an open PR #7. `acme-web` has a plan `20261127-110000-invoice-screen.md` with `- **Tickets**: example/acme-api#41` and `- **Waits for**: acme-api PR #7 merged`.
3. The owner opens ⋯ → ☑ Checklist and picks `acme-product`.
4. The drawer shows ticket `example/acme-api#41` with two rows: `invoice-export` (step "needs you", PR #7 open) and `invoice-screen` (step "waiting", `acme-api PR #7 merged ✗`).
5. The owner clicks ✎ Edit ledger. VS Code opens `~/.claude/pipeline-dashboard/groups/acme-product/ledger.md` with empty `## Goals`, `## Holds` and `## Notes`. The owner writes "Invoice export before 15 Dec" under Goals. The drawer shows it at the next refresh (5 s).
6. A chat runs `curl -s 'http://127.0.0.1:4899/api/ledger?group=acme-product'` and gets the same data as JSON.

## Contracts

- **Registry entry:** new optional field `group` (string, `safeGroup()` rule: 1–40 characters of `A-Z a-z 0-9 . _ -`, not `.` or `..`). Group names are lower case: `cleanEntry()` stores the value in lower case, and `resolveProject()` gives it in lower case (a hand-written `Acme-Product` is the group `acme-product`), because the name is also a folder name and the Mac file system does not see case. `resolveProject()` gives `group: ''` for a missing or bad value.
- **`/api/state`** (additive): each project object gets `group` (string, `''` when none). Each plan object (active and archived) gets `tickets`: `[{ repo, number }]` from its `- **Tickets**:` header line (`repo` is `'owner/name'` or `null`), `[]` when there is no line.
- **`GET /api/ledger?group=<group>`** → 200:
  ```json
  { "group": "acme-product",
    "projects": [{ "name": "acme-api", "short": "", "color": "" }],
    "ledger": { "path": "~/.claude/pipeline-dashboard/groups/acme-product/ledger.md", "exists": true, "text": "# Ledger …", "truncated": false },
    "chain": {
      "tickets": [{ "key": "example/acme-api#41", "url": "https://github.com/example/acme-api/issues/41", "done": false,
        "plans": [{ "project": "acme-api", "slug": "20261127-100000-invoice-export", "title": "Invoice export",
          "step": "needs-you", "pr": { "number": 7, "state": "OPEN", "url": "https://example.test/pull/7" },
          "waits": null, "archived": false }] }],
      "untracked": [] },
    "questions": { "source": null, "items": [], "note": "No question source is set up yet." } }
  ```
  - `step` is one of `done`, `closed`, `running`, `failed`, `needs-you`, `waiting`, `planned` (rules in `planStep()`, step 2).
  - `waits` is `null` or a list of `{ text, met, error }` (`error` is `null` or the watcher's short reason).
  - 400 `{ error: 'bad group' }` for a missing or malformed group, or for a group that no registered project has.
  - 500 `{ error: 'Cannot build the state. See server.log.' }` when the state build fails (a fixed text).
  - `ledger.error` (string) is there only when the file exists but cannot be read; then `text` is `''`.
- **`POST /api/ledger/open`** with `{ group }` → 200 `{ ok: true, path, created }`, 200 `{ ok: false, output }` when the file cannot be written (the page's `post()` shows `output`), or 400 `{ error: 'bad group' }`.
- **The file `~/.claude/pipeline-dashboard/groups/<group>/ledger.md`:** free Markdown. The template that `POST /api/ledger/open` writes is `ledgerTemplate(group)` (step 2). The server reads at most 256 KB of it.
- Consumers: the page (`renderChecklist()`); later the phase 3 conductor and the `dash` CLI. `apps/dashboard/state-load.mjs compare` compares `/api/state` bodies of two dashboards; two builds of the same code give the same new fields, and a compare of an old build with a new build shows `group` and `tickets` as a difference (expected).

## Steps

1. Create `apps/dashboard/groups.mjs`. Header comment like `watch.mjs` ("Pure helpers of the group ledger … No imports and no side effects"), and a doc comment on each export in ASD-STE100:
   - `safeGroup(s)`: true when `s` is a string that matches `/^[A-Za-z0-9._-]{1,40}$/` and is not `.` or `..`.
   - `parseTickets(content)`: the header is the text before the first line that starts with `## `; lines inside ``` fences do not count (the loop of `parseWaitsFor()`). The first line that matches `/^\s*[-*]\s*\*\*Tickets\*\*:\s*(.+?)\s*$/` counts. Its value, with backticks removed, is split on `/[\s,;]+/`. Each part that matches the whole pattern `/^(?:([\w.-]+\/[\w.-]+))?#(\d{1,7})$/` gives `{ repo: m[1] || null, number: +m[2] }`; a part that does not match the whole pattern (`abc#41`, `#12345678`, `acme-api#41`, an issue URL, `none`) is skipped, so a fragment never becomes a ticket. Repeats (same repo and number) are removed. No line, or a value with no valid part, gives `[]`.
2. In `apps/dashboard/groups.mjs`, add:
   - `ticketKey(t, issuesUrl, project)`: `t.repo` set → `{ key: t.repo.toLowerCase() + '#' + n, url: 'https://github.com/' + t.repo + '/issues/' + n }`; else `issuesUrl` matches `/^https:\/\/github\.com\/([^/]+\/[^/]+)\/issues\/$/` → `{ key: m[1].toLowerCase() + '#' + n, url: issuesUrl + n }`; else `{ key: project + '#' + n, url: null }`. The key is lower case because GitHub owner and repo names are not case-sensitive; the URL keeps the case as written.
   - `planStep(p, now, staleMs)` for one `/api/state` plan object; the first rule that matches wins: `done` (`p.archived`, or `p.pr?.state === 'MERGED'`); `running` (`p.live`, or `p.launch?.state === 'starting'`, or a fresh running report: `p.run?.outcome === 'running'`, `p.reportAt` newer than `now - staleMs`, and `p.run.status` does not start with `CLEANED` or `unknown` — the rule of `runningCount()` in `watch.mjs`); `closed` (`p.pr?.state === 'CLOSED'`: a closed PR with nothing running); `failed` (`p.launch?.state === 'failed'`, or `p.run?.outcome === 'failed'`, or a `running` report that is not fresh and whose status does not start with `CLEANED` or `unknown`: the run ended without a result). A report whose status starts with `CLEANED` or `unknown` (`auto-pipeline.sh --cleanup` writes `CLEANED`, and `outcomeOf()` gives `running` for it) counts as no run: the rules below decide; `needs-you` (`p.run?.outcome === 'needs-you'`, or `p.chatWaits > 0`, or `p.pr?.state === 'OPEN'`); `waiting` (`p.waits` has an item with `met: false`); else `planned`.
   - `buildChain(projects, now, staleMs)` for the `/api/state` project objects of one group (each with `name`, `issuesUrl`, `plans`). Each plan gives a row `{ project, slug, title, step: planStep(p, now, staleMs), pr: p.pr ? { number, state, url } : null, waits: p.waits ? p.waits.map(({ text, met, error }) => ({ text, met, error: error || null })) : null, archived: !!p.archived }` (the `error` of a wait, for example "unknown project", tells the owner why it is ✗). An active plan with tickets goes into each of its tickets (through `ticketKey()`), at most once per ticket key (`#41` and `example/acme-api#41` in an `acme-api` plan give one row). An archived plan with tickets goes only into tickets that also have an active plan. An active plan without tickets goes into `untracked`; an archived plan without tickets is left out. Rows in a ticket and in `untracked` are sorted by `slug` (the date prefix). Tickets are sorted by their first row's `slug`. Each ticket is `{ key, url, done: every row's step is 'done', plans }`. Returns `{ tickets, untracked }`.
   - `ledgerTemplate(group)`: `'# Ledger: ' + group + '\n\nGoals, holds and notes of this group. The dashboard computes the tickets, plans and PRs by itself.\n\n## Goals\n\n## Holds\n\n## Notes\n'`.

6. `apps/dashboard/server.mjs`: after `openInVsCode()`, add a "group ledger" block with doc comments:
   - `const LEDGER_DIR = path.join(CENTRAL, 'groups');` and `const ledgerFile = (group) => path.join(LEDGER_DIR, group, 'ledger.md');`
   - `groupProjects(group, stateProjects)`: the items of `stateProjects` whose `group === group`.
   - `async ledgerState(group)`: `null` when `!safeGroup(group)`. Else `const st = JSON.parse((await buildStateBody()).body)` inside `try`; a failed build returns `{ failed: true }`, and the route answers 500 `{ error: 'Cannot build the state. See server.log.' }` (a fixed text, no internal detail; the error goes to the server log with `console.error`). `buildStateBody()` shares a build that started less than 1 s ago (`STATE_CACHE_MS`), else it builds once more, the same cost as one `/api/state` poll. Then `const projs = groupProjects(group, st)`, `null` when `projs` is empty. Read the file with `openSync`/`readSync` into a `Buffer` of at most 256 KB (`LEDGER_MAX = 256 * 1024` bytes), decode it with `new StringDecoder('utf8').write(buf)` (`import { StringDecoder } from 'node:string_decoder'`, a Node built-in): the decoder holds back the bytes of a multi-byte character cut at the limit, so a cut character is dropped and a real `'�'` in the file is kept. `fileState(f)` (a small local helper) gives `'file'`, `'none'` (`ENOENT`, `ENOTDIR`, a dangling link, or a path that is not a file) or `'error'` (any other `statSync` error, for example `EACCES`). `exists` is false for `'none'`. `truncated` is true when the file is larger than `LEDGER_MAX`. `'error'`, or an error of the read itself (for example no permission), gives `exists: true`, `text: ''` and `error: 'Cannot read the ledger: <code>'`, never a 500. Return the **Contracts** shape, with `path: tilde(ledgerFile(group))`, `chain: buildChain(projs, Date.now(), STALE_RUN_MS)` (the watcher's constant: a `running` report older than 30 minutes with no process is a dead run), `questions: { source: null, items: [], note: 'No question source is set up yet.' }`.
   - `ledgerOpen(group)`: `null` when `!safeGroup(group)` or no registry project (`allProjects()`) has this group.
